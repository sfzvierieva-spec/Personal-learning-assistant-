# Database Documentation

## Overview

The Personalized Learning Platform uses an SQLite database named
`learning_platform.db`, created by `create_database.py` from `schema.sql`.

It stores:

- Learner profiles
- Uploaded courses
- AI-generated content
- User feedback

## Table descriptions

### profiles

Stores the learner profile built from the questionnaire.

| Field | Type | Description |
|-------|------|-------------|
| id | INTEGER | Primary key |
| profile_json | TEXT | The full `Profile` serialized as JSON (must be valid JSON) |
| created_at | TIMESTAMP | Creation date |

`profile_json` follows the `Profile` pydantic model defined in
`profile_and_prompts/profile/schema.py`:

| Profile field | Type | Example values |
|---------------|------|----------------|
| main_format | list of strings | `synthesis_sheet`, `flashcards`, `quiz`, `mindmap`, `worked_examples`, `revision_plan`, `exam_questions` |
| density | string | `dense`, `balanced`, `spacious` |
| explanation_style | string | `definition_only`, `definition_plus_example`, `definition_plus_analogy`, `step_by_step` |
| struggle | list of strings | `too_abstract`, `too_dense`, `hard_to_remember`, `hard_to_apply`, `boring` |
| study_goal | string | `mcq_exam`, `essay_exam`, `oral_exam`, `practical_application`, `personal_understanding` |
| self_testing | string | `mainly_reading`, `reading_with_checks`, `mainly_testing` |
| tone | string | `textbook`, `teacher_voice`, `friend_explaining`, `raw_notes` |
| visual_layout | string | `structured_paragraphs`, `bullet_lists`, `tables_when_comparative`, `mixed_with_diagrams` |

It also contains `free_text_notes` and `metadata` (timestamp, questionnaire
version). `schema.py` is the source of truth for the exact values.

Writing and reading a profile:

```python
conn.execute("INSERT INTO profiles (profile_json) VALUES (?)",
             (profile.model_dump_json(),))

row = conn.execute("SELECT profile_json FROM profiles WHERE id = ?", (1,)).fetchone()
profile = Profile.model_validate_json(row[0])
```

### courses

Stores uploaded courses.

| Field | Type | Description |
|-------|------|-------------|
| id | INTEGER | Primary key |
| profile_id | INTEGER | Related profile |
| course_name | TEXT | Course title |
| file_path | TEXT | Location of the uploaded file |
| upload_date | TIMESTAMP | Upload date |

### generations

Stores content generated by the AI.

| Field | Type | Description |
|-------|------|-------------|
| id | INTEGER | Primary key |
| profile_id | INTEGER | Related profile |
| course_id | INTEGER | Related course |
| prompt | TEXT | System prompt / request sent to the model |
| generated_content | TEXT | AI output |
| generation_date | TIMESTAMP | Generation timestamp |

Examples: summaries, quizzes, flashcards, study guides.

### feedbacks

Stores user ratings and comments.

| Field | Type | Description |
|-------|------|-------------|
| id | INTEGER | Primary key |
| profile_id | INTEGER | Related profile |
| generation_id | INTEGER | Related generation |
| rating | INTEGER | Score from 1 to 5 (enforced by a CHECK constraint) |
| comment | TEXT | User feedback |
| feedback_date | TIMESTAMP | Submission date |

Rating scale: 1 = Poor, 2 = Fair, 3 = Good, 4 = Very good, 5 = Excellent.

## Relationships

```text
profiles    (1) -----> (N) courses
profiles    (1) -----> (N) generations
courses     (1) -----> (N) generations
generations (1) -----> (N) feedbacks
```

Foreign keys are enforced (`PRAGMA foreign_keys = ON` in `schema.sql`; it must
also be set on every new connection, since SQLite turns it off by default).

---

## Design choices

- **Profile stored as JSON.** The `Profile` model changes as the questionnaire
  evolves. Storing it whole in `profile_json` keeps the table stable and avoids
  a migration every time a field is added. If we need to filter on one field
  (e.g. `study_goal`), we will add a dedicated column at that point, or use
  SQLite's `json_extract(profile_json, '$.study_goal')`.
- **Schema in a `.sql` file.** The table definitions can be reviewed without
  reading Python, and `create_database.py` stays a thin runner.
- **SQLite.** Lightweight, no server, ships with Python — enough for this
  project.
