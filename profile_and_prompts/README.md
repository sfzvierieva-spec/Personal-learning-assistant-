# Profile & Prompts module (Pole 1)

The "brain" of the personalized study agent. This module profiles a learner
through a short questionnaire, turns the answers into a validated profile
object, and generates the personalized system prompt that the downstream
agent (`ingestion_generation`) will send to the LLM when producing study
material.

## Pipeline

```
questionnaire answers
      → build_profile()           → Profile (pydantic object)
      → summarize_profile()       → warm-but-neutral summary  [user validates]
      → generate_system_prompt()  → system prompt string      [→ ingestion_generation]
```

The profile is validated with pydantic before it leaves this module, so the
rest of the app never has to deal with raw user input.

## Contract exposed to the other poles

```python
from profile_and_prompts.questionnaire.questions import QUESTIONS
from profile_and_prompts.profile.builder import build_profile, summarize_profile
from profile_and_prompts.prompt_generator.generator import generate_system_prompt

profile = build_profile(answers)              # dict → validated Profile object
paragraph, bullets = summarize_profile(profile)  # shown to the user before generation
system_prompt = generate_system_prompt(profile)  # passed as `system=` to the LLM
```

`QUESTIONS` is the list the interface renders (`interface/ui/screens/questionnaire.py`).
`generate_system_prompt(profile)` is the string `ingestion_generation.generate_content()` passes to the LLM.

## Design principles

- **Output-shaping questions only.** Every question in the 8-question
  questionnaire maps to a concrete decision in the generated material (format,
  density, explanation style, blockers, study goal, reading-vs-testing
  balance, tone, visual layout). Questions that didn't change the output
  (chronotype, spacing habits) were removed between v1 and v2 of the
  questionnaire. See the commit history for the pivot.
- **Warm but not sycophantic.** `summarize_profile()` interprets the answers
  into short observations ("you don't trust that just reading is enough —
  you want to remake the material yourself") rather than listing them back
  verbatim. It never comments on the person (no "motivated", no
  compliments) — just methods and patterns.
- **No LLM inside this module.** The summary and the system prompt are both
  generated by templates. That makes outputs deterministic, testable, and
  immune to drift.

## Failure modes mitigated here

The system prompt v4 includes a `<forbidden>` block that explicitly addresses:

- **Sycophancy** — the LLM is forbidden from flattering the user or judging
  their character.
- **Hallucination** — the LLM is forbidden from inventing facts not present
  in the course; it must say "the source does not contain this information"
  when the course is thin.
- **Prompt injection** — course text is declared as data, never as
  instructions.

`prompts/EVALUATION.md` reports the real-run evidence for each (from
David's `outputs/v1_vs_v4/` runs) and names the known residual issue —
v4's "why" explanations sometimes add facts from the model's knowledge
rather than the course. That's the target of v5.

## How to run the tests

```bash
pip install -r requirements.txt          # from the repo root
python3 -m pytest profile_and_prompts/tests/test_end_to_end.py -v
```

Expected: 4 tests pass. The tests run 3 contrasting fake users through the
whole pipeline (questionnaire → profile → summary → system prompt) and
check that:

- the pipeline runs for every profile;
- the generated prompts are visibly different between profiles (real
  personalization, not cosmetic);
- the free-text "Other" nuance is preserved end-to-end;
- the guardrails are present in every generated prompt.
